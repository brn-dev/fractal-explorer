# Fractal Explorer for Android

The web explorer runs offline inside an Android WebView, using its bundled copy or a downloaded web update. The same APK adds separate cover/main wallpaper designs, native video encoding, package import, and a native live-wallpaper player. The wallpaper plays pre-rendered videos; it does not keep the WebView or fractal renderer running behind the home screen. Hinge tracking and Shizuku are not needed.

The APK is generated at `../artifacts/android-wallpaper/fractal-wallpaper.apk`. Version 0.14.0 uses the same application ID and development certificate as the earlier player prototype, so it installs as an update. Open **Fractal Explorer**, then use **Export → Create wallpaper**. **Wallpaper gallery** opens your saved collection; **Wallpaper settings** opens native playback settings and imports. **Set up on both screens** opens the inner/cover setup guide described below.

The explorer shares its WebGPU recovery with the website: it verifies the current scene's compute pipeline before declaring the GPU ready, compiles smaller formula-specific kernels, and retries internal Vulkan pipeline failures up to three times. A persistent failure or lost device switches exploration to CPU rendering; **Rendering → Retry GPU** can reconnect without restarting or changing a paused fractal. The actual Adreno startup issue still needs confirmation on the phone; local Chrome tests deliberately inject the error and exercise both recovery paths. Native wallpaper playback is unaffected by the explorer's GPU availability.

## Explorer updates without reinstalling

Web updates have been supported since APK 0.12.0. Install the current APK 0.14.0 for native weighted/time-filtered shuffle support. When the explorer opens, it checks the project's published GitHub Pages site at most once a day, and downloads a newer compatible web bundle. **Check for updates** under **Rendering → Performance lab** checks immediately. Once a complete update is ready, **Reload update** saves the explorer session and loads it. **Later** keeps the current version running; it is never replaced during editing or rendering. Save your scene or finish/cancel exports and close open dialogs before reloading. Both the APK copy and downloaded updates work offline. Wallpaper playback does not run the updater or require an internet connection.

The native toolbar's **⋮ → Explorer updates** menu also checks/reloads updates, and **Restore bundled** returns to the explorer shipped in the APK. Recovery is available even if the web UI cannot start. An update that never acknowledges startup rolls back to the previous working web copy on reopening. A restored/failed web release is skipped until a newer release appears. Gallery packages and web draft storage are separate from update storage and are not deleted by activation or recovery. Native wallpaper playback, Android encoding/bridge changes and new permissions still require an APK update.

Publishing remains the normal workflow: push the web changes and let the existing Pages workflow finish. `npm run build` now creates `dist/android-web/latest.json` and a versioned ZIP alongside the website. The existing Pages artifact includes them automatically; no second release upload or CI secret is needed. The APK excludes those publication ZIPs and includes only its standalone explorer. Browser service-worker caches also exclude the Android publication files. The web release timestamp comes from the Git commit (or `SOURCE_DATE_EPOCH`) and prevents an older published site replacing newer bundled content.

`web/android-compat.json` declares the minimum Android `versionCode` for a web release. The current value is 24 because weighted selection and solar scheduling need APK 0.14.0. Keep it at 24 for subsequent web changes using this native API; raise it when new native functionality is required. An older host keeps its working explorer and reports that an APK update is needed. The downloader accepts only the fixed HTTPS project endpoint and expected bundle filename, with redirects disabled, archive/per-file SHA-256 checks, path/size/count limits and complete ZIP validation. Its trust source is the published HTTPS site; bundles are not independently digitally signed. Complete bundles are installed atomically and pinned to each running WebView until explicit reload, under the same local origin as before. Arbitrary web navigation and WebView network loads remain blocked. Only the native downloader uses the Internet permission.

## Static wallpapers

In **Export → Create wallpaper**, choose the target screen/device and **Wallpaper type → Static image**. **Edit image** opens the target-shaped frame with parameter animation and color cycling disabled. Save the image scene, choose resolution and supersampling, then **Create main / cover wallpaper**. This renders a single lossless PNG and saves an image-only gallery entry, without encoding any video. Switching back to Animated retains the saved transition start, loop and timing settings.

On PC, the main download button creates an editable wallpaper ZIP containing the PNG and design. Import that ZIP with **Wallpaper settings → Import wallpaper package**. **Download PNG image** exports just the image; **Wallpaper settings → Playback for → Main / Cover → Import static image** can import that PNG or an existing JPEG/WebP. Raw image imports have no editable fractal scene. The selected target is retained while the document picker is open. Imports normalize to an opaque sRGB PNG, filling transparency with black, and scale down only if a side exceeds 4096 pixels; playback center-crops to the target screen.

In **Wallpaper gallery**, select **Include in shuffle** for any mixture of images and animated wallpapers, then enable **Shuffle on each reveal**, separately for each screen. A static pick displays only its image: no video player, idle loop or arrival extraction starts. The next fresh reveal can pick another image or an animation. Animation preferences remain saved and apply when an animated entry is picked. As before, an initial reveal, a fold/display event, or returning after at least two seconds can advance the selection; a quick lock/home handoff shares one selection. Battery Saver still selects designs but displays their still images. Importing/creating an entry selects it alone; enable shuffle again after adding it to the desired screen's pool.

## Create the four states

**Target device → Samsung Galaxy Z Fold8 Ultra** lets you start directly on a PC without a phone link. It selects exact portrait dimensions: cover **1080 × 2520**, main **2256 × 2504**, as listed by [Samsung for SM-F976B](https://www.samsung.com/ie/business/smartphones/galaxy-z/galaxy-z-fold8-ultra-violet-shadow-256gb-sm-f976bzvbeub/). The preset selects **Match target screen exactly**; smaller output sizes remain available. Explicit presets stay selected when a different phone display is detected. **Saved or detected screen** uses imported/detected dimensions; **Detect resolution** switches to the current phone's measurements when available.

**Edit start scene** and **Edit end / steady scene** show the whole target rectangle with a border and dimension label. The interactive canvas uses the export's proportions, including when the PC or current phone screen has a different shape. Pan, pinch, wheel zoom and parameter edits compose directly within that frame, without changing the scene just to fit the editor. The frame fits above the scene toolbar and follows window resizing. Mobile controls collapse on entry and their previous collapsed/expanded state returns on leaving the scene. **Save scene** or **Back to overview** restores the regular explorer viewport. Without exact native dimensions, the frame is labelled **screen proportions** until a device or screen size is supplied.

| State | Playback |
| --- | --- |
| Just closed | Starts when the cover becomes active, plays once, then reaches Closed. |
| Closed | Holds the small display's still image or repeats its steady animation. |
| Just opened | Starts when the inner screen becomes active, plays once, then reaches Open. |
| Open | Holds the large display's still image or repeats its steady animation. |

1. Open **Export → Create wallpaper** and choose **Design for → Main screen / Cover screen**. Switching screens keeps each working draft separately, including its name, timing and quality settings.
2. Design **Open / Closed** with **Edit end / steady scene**; it is both the transition endpoint and the first loop frame. Then edit **Just opened / Just closed** with **Edit start scene**. You can also build either endpoint first: save it, then use **Copy start → end** or **Copy end → start** to replace the other saved scene and preview the copy. **Edit** the destination to adjust it independently. Copying uses saved geometry, palette and rendering settings; the source stays independent. Start scenes have no parameter motion, and copying a start to the end establishes a still geometry baseline for adding loop motion there. Shared color cycling and transition timing stay linked. View start/end previews the saved scenes. Parameter automation belongs to the steady scene and is disabled while editing a start.
3. Set transition duration and motion curve. Geometry uses the selected easing; the default starts fast and eases out.
4. Choose **Colors in both scenes** and **Color cycle · seconds**. Both clips use the same palette, density and constant color speed; palette edits in either scene update both. The effective period fits whole cycles into the loop and is displayed. Transition phase is offset to match the loop's first phase exactly. **Keep colors still** disables color motion in both. Different formulas/settings blend with the same palette.
5. Choose animated steady playback or transitions only, idle duration, resolution and frame rate. The minimum loop duration grows as needed to preserve every chosen parameter speed exactly, without retiming individual channels. Preview the pair.
6. Tap **Create main / cover wallpaper**. Only that screen's two clips and poster are rendered and saved; the other selection is unchanged. Use **Set up on both screens** if Samsung still needs its wallpaper components assigned. Gallery switches then require no rendering.

**Resolution** defaults to **Match this screen exactly** on Android. Open the app once on each panel (folded and unfolded) so it records both physical display modes, then use **Detect resolution** if needed. Android dimensions are authoritative: imported sizes from another phone cannot pretend to be detected local pixels. Browser exports may use dimensions saved in an exported draft. The 480 px designer preview is separate from full-resolution export.

**Fractal supersampling** inherits the explorer setting when creating a design or saving either scene, and can also be set explicitly in the wallpaper designer. 2× renders twice the width and height (four samples per output pixel); the colored image is downsampled before video encoding. Both clips and the matching poster use the same sampling. Video dimensions stay at the chosen resolution. This increases creation time and memory use, with no additional playback rendering. Old drafts default to 1×. Requests above the current renderer's dimension/pixel limits fail clearly; sampling is never silently reduced. A GPU failure also rechecks the smaller CPU limits before starting fallback work.

Wallpaper preview and export color GPU fields directly on the GPU before downsampling. One-use morph-transition frames do not make full-resolution CPU copies or temporary cache writes. Palette-only frames keep the same field resident. Returning parameter states retain lossless caching; after RAM fills, a measured storage-cost probe avoids disk caching for GPU fields that are cheaper to recompute. Expensive fields can still spill to temporary storage. Resolution, supersampling, scene samples and encoding quality stay as selected. CPU fallback uses the existing CPU coloring, and device loss during a GPU paint fails before that frame can be encoded.

## Render on your PC

Native resolution with supersampling can take a long time on a phone. You can design on the phone and render the same wallpaper using the PC browser's GPU instead:

1. In the phone's wallpaper designer, finish saving the start and steady scenes, choose the screen's native resolution, sampling and quality, then tap **Render on PC…**. No videos are rendered during this step.
2. **Copy PC link** or **Share PC link…** and open it on your PC in Chrome or Edge. The link contains the selected screen's two scenes, exact decimal parameters, animation, palette, timing, resolution and quality. It opens the wallpaper designer after the browser renderer initializes; an existing working draft is replaced only after confirmation.
3. Check **GPU rendering** below the designer. If it says CPU, use **Rendering → Retry GPU** before starting a large export. Choose **Download main / cover wallpaper** and keep the tab visible until it finishes. This creates a ZIP containing that screen's rendered videos, poster and editable design.
4. Transfer the ZIP to your phone. In **Wallpaper settings → Import wallpaper package**, select it. The app keeps it in your gallery and selects it for that screen, with no phone-side fractal rendering. The other screen's selection is unchanged.

If the link is too long, **Download PC draft** always remains available for supported drafts. Transfer the JSON file to your PC and use **Export → Create wallpaper → Open wallpaper draft**. It preserves the phone's screen dimensions; the PC monitor's dimensions do not replace them. Ordinary **Save draft** also supports this route. Link payloads are gzip-compressed where supported, stay in the URL fragment, and have a practical 12,000-character cap and 128 KiB decoded-data limit; larger designs use the JSON file (up to 4 MiB). Invalid/truncated links and oversized decompression are rejected before modifying a draft. The published web app must include this handoff version for link opening and wallpaper supersampling support.

**Video quality** offers **Dynamic · High** (recommended for new designs) and **Dynamic · Balanced** (smaller files), plus the existing Draft/Balanced/High/Ultra/Extreme/Maximum and custom 0.5–600 Mbps targets. Existing drafts retain their selected quality. Dynamic High requests H.264 QP 22 in the browser; Dynamic Balanced requests QP 26. These are moderate constant-quality levels, so simple sections can use fewer bits and complex sections more. File size and peak bitrate are not capped. If CQ is unavailable, each uses a moderate VBR target based on output pixels and frame rate (High: 0.18 bits/pixel/frame, up to a 60 Mbps target; Balanced: 0.10, up to a 35 Mbps target). These are bitrate targets, not hard ceilings. At 2256×2504 / 30 fps the fallback targets are about 30.5 and 16.9 Mbps; at 15 fps they are half as large.

Android CQ quality uses each codec's implementation-specific quality scale, mapped below its maximum for moderate modes. A codec exposing only one CQ level uses the moderate VBR fallback instead. The UI reports the chosen native mode before creation, the actual browser/native mode as each clip starts, then the finished file size and average bitrate. These file averages include MP4 overhead. Browser CQ and Android quality scales do not guarantee identical compression. Ordinary presets and Custom also explicitly use VBR. Maximum retains browser QP 0 with no browser bitrate fallback; Android retains its highest CQ or highest advertised VBR behavior. None of these modes guarantees lossless encoding or a fixed file size. Android-generated clips/package imports support up to 1 GiB per video and 3 GiB per package; manual Choose-video imports retain their 150 MB limit.

Steady editing, saved preview and exported clips share parameter rates and a palette clock. Saving mid-cycle preserves the baseline color/geometry relationship. Palette motion follows the parameter clock through cache warmup, pause, edits while paused, and resume, including full color laps beyond the shorter shape loop.

Legacy drafts without transition overrides remain readable and use the earlier global arrival duration, with the new fast-start default when rendered again. Select Slow start explicitly to recreate the old curve. Existing saved videos, including bundled samples, stay unchanged until you replace/render them.

While editing a **transition start**, parameter automation and color wandering are disabled: it is a still endpoint, and the transition curve defines its motion. Manual parameter values, sliders, precision controls, and color phase remain editable. Saved legacy motion is suppressed on a detached editing copy; Back preserves the saved design, while Save stores the start without ignored motion. Leaving start-scene editing restores the controls. **End / steady scenes** retain animation controls because they define the steady loops.

## Set up the inner and cover screens

On Samsung Fold, Home/lock destinations and inner/cover displays are separate choices. The setup guide shows which display is active and enables the appropriate step. Set the inner screen while open, then fold, wake/unlock the cover, reopen the app if needed, and set the cover. Choose Home and lock in each system preview when offered.

The inner step uses **Fractal Wallpaper**; the cover step uses the separately registered **Fractal Wallpaper · Cover** entry. This gives the picker another selectable component when it will not reapply the existing entry. Both entries share the gallery/media/preferences and remain adaptive to the actual display. If the direct preview has no Set button, the guide can open the public live wallpaper chooser; while folded, select the Cover entry there.

The app does not claim success merely because the picker returns. Check home and lock on both screens. Samsung ultimately controls wallpaper assignment; the new Cover entry is a public-API workaround and has **not been confirmed on the physical Fold**. There is no hidden Samsung API, overlay, Shizuku, or new permission involved.

Drafts persist in WebView/browser storage and can also be saved/opened as JSON. Drafts and package metadata support up to 4 MiB of UTF-8 JSON, including long exact constants and automation targets; metadata size is checked before video rendering. Custom formulas, custom constants, palettes, and parameter automation use the existing web renderer. In an ordinary desktop/mobile browser, the same editor downloads `fractal-wallpaper.zip`; transfer it to the phone and use **Wallpaper settings → Import wallpaper package**. Each new ZIP contains the selected screen's two MP4s, one poster, playback mapping and editable draft. Older combined seven-file packages remain accepted. Imported packages with an editor draft can now be reopened through **Wallpaper gallery → Edit design**; JSON **Save draft / Open wallpaper draft** also remains available for portable editing.

## Weighted shuffle and day/night filters

Install APK **0.14.0**. In **Wallpaper gallery**, choose main or cover, select **Include in shuffle**, and set each selected wallpaper's **Shuffle weight** and **Time filter**. Press **Save shuffle settings** on that card, then enable **Shuffle on each reveal**. Rules default to weight **1** and **Any time**, and are retained when you uncheck/recheck an entry. Cover and main rules are independent, including for older combined packages.

Weights range from **0.1 to 100**. If eligible entries have different weights, weight 2 gets twice the selection probability of weight 1; the same entry may repeat, otherwise two entries would simply alternate regardless of their weights. When all eligible weights are equal, the existing repeat avoidance remains in effect. Weights apply equally to static and animated entries.

**Daytime** means sunrise (inclusive) to sunset (exclusive); **Nighttime** means sunset to the next sunrise. **Any time** qualifies for both. The fixed Vienna-area coordinates (48.2082 N, 16.3738 E) use approximate [NOAA solar equations](https://gml.noaa.gov/grad/solcalc/solareqns.PDF), calculated offline for each date. `Europe/Vienna` handles local dates and daylight saving time, independently of the device's display time zone. The gallery shows today's estimated sunrise/sunset and eligible count. No location permission or weather service is used; these are seasonal estimates, not observations of weather or nearby hills. Travel does not change the fixed Vienna location.

A visible wallpaper reevaluates at the next sunrise/sunset, and date/time/time-zone changes reschedule it. Hidden/off-screen wallpapers have no timer or wakeup; the next reveal checks the current time. If no selected entry qualifies (or eligible files are unavailable), the player stops video and shows neutral black until a later eligible selection. It keeps the saved gallery and active ID intact. Turning shuffle off or **Use only this** returns to the selected wallpaper without a time filter.

## Save and switch wallpapers

Completed renders and imported packages are automatically retained in the Android **Wallpaper gallery**, with a thumbnail, name, and storage size. Older retained packages from an existing installation also appear. There is no fixed entry limit; videos use phone storage until you delete them.

- **Wallpapers for → Main screen / Cover screen**, then **Use on main / cover**, changes only that screen. Older combined wallpapers appear in both lists. Playback preferences and active package/revision are separate per screen. Native **Wallpaper settings → Playback for** also changes only the selected screen.
- To rotate designs, check **Include in shuffle** on the desired gallery entries, then enable **Shuffle on each reveal**. Each screen has its own saved selection, supporting both image-only and animated entries. A fresh reveal chooses from wallpapers eligible at that time. Equal weights avoid the current design when another candidate exists; unequal weights use relative odds and may repeat. Lock/home engines share one choice for the same reveal. Returning after at least two seconds, initial display and fold events can trigger selection; resizing, picker previews and known external displays cannot. Shuffle works with arrivals disabled and in Battery Saver; the current screen's playback options apply to animated picks. **Use only this**, or creating/importing a new design, switches that screen back to one fixed wallpaper while retaining its shuffle selection for later. Delete requires removing a design from any enabled shuffle selections first.
- **Duplicate & edit** opens a named copy of an editable design for the selected screen, including static images created with their fractal scene. Existing names get a numbered copy suffix when needed. Edit its scenes/palette (for example, choose a dark palette), then **Create** to render and save the variation as a separate gallery entry. The saved original and current wallpaper selection remain intact while editing. Imports containing only pixels/videos have no editable fractal scene, so this action is disabled for them.
- **New wallpaper** starts a fresh design from the current explorer scene. **Edit design** loads the selected screen's saved pair; older combined designs are split without modifying the original. New, Edit and Duplicate ask before replacing a working draft; use **Save draft** to keep unfinished edits. Rendering an edited design saves a new gallery entry and preserves the original.
- **Rename** changes the saved name. **Delete** asks before removing that entry's videos and design. Select another wallpaper on every screen using that design before deleting it.
- Packages made from individually chosen MP4s can be applied, renamed, and deleted, but have no fractal design to reopen. Each completed individual-clip import saves a new package while keeping older versions.
- **Restore sample videos** keeps the gallery intact. Gallery switching and new-package activation wait for pending native imports to finish.

The collection is private to this app on this phone. It survives normal restarts and compatible APK updates. Uninstalling or clearing app data removes it; a saved JSON draft backs up its editable design, not its rendered videos. The ordinary browser retains its existing draft/ZIP workflow and does not expose the Android gallery.

## Playback

- The bundled sample arrival lasts 2.8 seconds at 30 fps. Its idle loops last 8 seconds at 15 fps. The designer defaults to a 3-second arrival and an 8-second idle, with adjustable durations and 10–30 fps idle playback.
- The cover sample is 720 × 1680; the inner sample is 1080 × 1200. Both are silent H.264, generated on the computer with the existing fractal renderer. Video and poster textures are center-cropped to the wallpaper surface, including landscape.
- The arrival's final raw image exactly matches idle frame zero. Idle shape and palette motion return to their start without a deliberate hold or duplicate final frame. When switching from arrival to an animated idle loop, the compositor retains the final decoded video image until the next decoder supplies a frame. This avoids briefly displaying the sharper lossless PNG between two compressed clips. The old decoder is released immediately; its retained image resources are released after the first new frame, or on hide, artwork changes, errors and shutdown. The PNG remains the static/fallback image. Each decoder has its own surface/texture queue, and retired frame callbacks cannot replace new artwork. Ordinary idle repeats keep the same decoder and texture. Actual handoff timing needs physical-device testing.
- Before an arrival's first video frame, the player displays a full-size image decoded from that transition at time zero. It caches one start texture per engine/artwork, releasing the temporary retriever and CPU bitmap immediately. This works with existing packages, including individually replaced clips. Mode/content changes invalidate the cache; disabled arrivals and Battery Saver skip extraction. If extraction fails, the player clears to black until video arrives, rather than flashing the steady endpoint, and retries extraction on a later arrival. A failed video still falls back to the steady poster.
- Visibility or a change between the narrow cover display and the almost-square inner display triggers playback. The public display-mode dimensions identify the composition independently of a launcher's scrolling wallpaper surface. There is no sensor listener or system display override.
- Returning to the wallpaper after at least two seconds also plays the arrival. A shorter visibility bounce resumes with the idle loop. A fold detected while hidden still triggers the new screen's arrival.
- **Play arrival animation** and **After the transition** are independent settings. Choose **Still image · transitions only** to show the steady poster after an arrival and release the video decoder. Choose **Animated loop while visible** to enable idle motion. All four clips are retained, so this can be changed without rendering again. New packages carry this preference; older packages preserve the current phone setting.
- Hidden wallpapers and screen-off release the video decoder. Battery Saver suppresses animation and keeps a still image. GPU presentation happens on decoded-frame callbacks, with no continuous application render timer.
- Each wallpaper engine owns its player, surface, and graphics context. Concurrent preview, video-encoding, and display engines share a reference-counted EGL display. Fractal calculation runs only inside the foreground explorer and during wallpaper creation; playback uses decoded video frames.

## Your own artwork

The app's four **Choose…** buttons import MP4 clips from the Android document picker. The app copies them to private storage, so the original files can move afterward. Clips can be 0.5–60 seconds, up to 4096 pixels per side and 150 MB each. Sound is muted. Use **Restore sample videos** to return to the bundled artwork.

In the web explorer, use **Export video**, choose MP4, disable sound and set **Hold final frame** to 0 for an idle loop. Parameter animations can alter the shape; a complete color cycle provides inexpensive palette movement. Render a separate arrival that ends at the loop's starting view. Custom clips are not automatically joined or made seamless by the app. With no explicitly selected steady clip, each new arrival import updates its endpoint still image, including repeated imports and imports for the other screen. Selecting an idle clip makes its first frame the steady image.

For automatic arrival/idle pairs from the local renderer, edit [`demo-scenes.json`](demo-scenes.json), including each screen's final view, arrival starting parameters, idle parameter offsets, and palette:

```powershell
uv run python scripts/render_wallpaper.py
# Or keep a separate set:
uv run python scripts/render_wallpaper.py --settings my-scenes.json --output artifacts/my-wallpaper
```

Run these commands from the repository root. FFmpeg must be on PATH; the renderer uses CUDA when available, otherwise CPU. This tool supports the desktop renderer's five formulas and limits. The web app's additional/custom formulas can be exported to MP4 there and imported with the app's pickers. Generated media is excluded from Git and must be rendered before building.

## Build

The app has no third-party Android runtime dependencies. It bundles the web app and its existing dependencies and license notices. Install the web dependencies with `cd web; npm ci` first. Open this directory in Android Studio with SDK 36 and a compatible Gradle installation (AGP 8.10.1; Gradle 8.11.1+), render the sample assets, then build the app. Both builds run the production web build and include the resulting static files. Android 11 / API 30 is the minimum; Node's existing web requirements apply.

There is also a Windows build using only an installed JDK and the official SDK's platform/build tools, without Gradle:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File android/build.ps1 `
  -JavaHome 'C:\Program Files\Java\jdk-21' `
  -AndroidJar 'C:\path\to\Sdk\platforms\android-36\android.jar' `
  -BuildTools 'C:\path\to\Sdk\build-tools\36.0.0'
```

The script does not download tools. Its defaults use the workspace-local SDK archives prepared under `../artifacts/android-tools/`. It normalizes Windows aapt2 asset paths before signing, so nested browser assets work in Android's AssetManager. Build output and the development signing key stay under `../artifacts/android-wallpaper/`. Gradle and the Windows script create/reuse this same key. Keep that key for compatible updates; it is not a production signing key. Application ID: `org.fractalexplorer.wallpaper`.

The host updater tests also use `artifacts/android-tools/json-20240303.jar` (test-only; Android supplies its own JSON runtime). Download it from `https://repo.maven.apache.org/maven2/org/json/json/20240303/json-20240303.jar`. The build verifies SHA-256 `3cf6cd6892e32e2b4c1c39e0f52f5248a2f5b37646fdfbb79a66b46b618414ed` before using it. The updater suite exercises real production ZIP/download/persistence/session code with local transport and actual Node-generated bundles. The bridge suite injects a worker, host and export fields without initializing Android codecs/UI; its host fixture uses JDK 21's `Unsafe`, which is not included in the APK.

The static wallpaper host suite exercises production import/storage/gallery code with real PNG/JPEG pixels through explicit ImageIO platform fixtures, including mixed carousel selections, failure rollback and file validation. These fixtures are compiled separately and never bundled into the APK. Actual Android ImageDecoder, provider UI, WebP decoding and physical wallpaper playback still require device testing.

Bundled resources are served under the pinned `https://appassets.androidplatform.net/explorer/` origin. External pages cannot navigate inside this privileged WebView. The narrow JavaScript bridge supports frame encoding, private staged packages, Android's document picker, and the wallpaper picker. Wallpaper exports use a native H.264 encoder with explicit frame timestamps; this also provides silent ordinary MP4 export when WebCodecs is missing (up to 4096 pixels / 16 MP, subject to advertised codec support; unsupported settings are rejected without changing their resolution or bitrate). Ordinary web MP4/soundscape exports retain their existing browser path when available. Renderer GPU availability depends on the installed WebView, with the existing WebAssembly worker fallback. APK updates update the bundled explorer; its browser service worker is intentionally bypassed inside Android.
